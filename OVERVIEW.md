# TriangleUI + HELIX — короткое техническое описание

Форк ChatterUI (Expo SDK 55, RN 0.83, New Architecture) с распределённым инференсом на
несколько телефонов. Движок — форк `cui-llama.rn` с включённым `GGML_RPC`
(`forks/cui-llama.rn-rpc`, JNI собирается с `-DLM_GGML_USE_RPC`). Python-пакет `helix/` —
референс и оракул соответствия; на проводе ничего Python-специфичного нет.

## Три режима

| Режим | Что делает | Модель |
|---|---|---|
| **Hybrid** | плейсхолдер, ничего не подключено | — |
| **Pointer** (Track A) | целые агенты обмениваются **результатами**; телефон-координатор раздаёт задачи, каждый агент отвечает своей моделью целиком | грузится целиком на каждом телефоне |
| **Sharder** (Track B) | модель **никогда не грузится целиком**: сначала метаданные, потом только те слои, которые уносит свободная память каждого устройства | разделена по кольцу |

Ключевое различие по смыслу, а не по скорости:

- **Sharder даёт ёмкость, не скорость.** Слои проходятся последовательно на каждый токен,
  так что это медленнее устройства, которое держит модель с запасом. Выигрыш — в том, что
  запускается то, что не влезает никуда поодиночке.
- **Pointer масштабирует пропускную способность** — несколько независимых ответов
  параллельно.

Известное ограничение планировщика: слои раскладываются **по памяти**, не по вычислительной
мощности. Медленный телефон со свободной RAM становится бутылочным горлышком конвейера.

## Протокол

Полная спецификация — [`HELIX_WIRE_SPEC.md`](HELIX_WIRE_SPEC.md); байтовая сверка —
`helix/spec/vectors.json` + `python -m helix.conformance`.

**Кадр (21 байт заголовка + тело):**

```
magic(4)="HLX1" | flags(1) | epoch(4,BE) | nonce(12) | sealed_body(...)
```

- `flags` бит 0 — confidential (AEAD) против auth-only (HMAC).
- Заголовок целиком идёт в AAD, поэтому `flags/epoch/nonce` неизменяемы в полёте.
- `MAX_FRAME = 16 MiB`, проверяется **до** аллокации на приёме.
- AEAD — ChaCha20-Poly1305 (RFC 8439), auth-only — HMAC-SHA256.
- Ключи из секрета кластера через HKDF-SHA256, метки `helix/1 aead key`,
  `helix/1 hmac key`, `helix/1 beacon key`.

**Сообщение** — компактный JSON `{v,t,seq,src[,tid][,b]}` внутри запечатанного тела.
Типы: `ANNOUNCE`, `HEARTBEAT`, `LEASE`, `LEASE_ACK`, `AGENT_ANNOUNCE`, `STATUS`, `TASK`,
`PARTIAL`, `RESULT`, `VOTE`, `DECIDE`, `CONTEXT_SYNC`.

**Транспорт.** Координатор — WebSocket-сервер на самом телефоне (порт по умолчанию 8790,
настраивается). Агент — встроенный в RN `WebSocket`, нативный модуль ему не нужен.
Слои в Sharder ходят отдельным каналом: llama.cpp `rpc-server` на каждом телефоне
(по умолчанию 50052), координатор строит `--rpc` список и `--tensor-split`.

**Сеть.** LAN, USB-tethering или прямой Wi-Fi (Android `LocalOnlyHotspot` +
`WifiNetworkSpecifier`), подключение по QR. BLE (BitChat) — **только** для внешних клиентов
без приложения; в Pointer/Sharder не участвует.

## Чаты и контекст

- Обычный чат приложения уходит в меш только в **Pointer** и только когда есть
  координатор и присоединившийся агент; иначе — обычный локальный путь.
- У Pointer и Sharder есть собственные чаты с **контекстными ветками**: ветка — полная
  копия ходов до точки развилки, чтобы можно было задать один и тот же вопрос двумя
  способами и увидеть, расходятся ли ответы. Это единственный честный способ проверить,
  что контекст действительно доезжает.
- История собирается в **один промпт** — истории на стороне агента нет. Обрезка идёт
  с начала, сколько ходов выпало — показывается. Логика вынесена в `lib/helixPrompt.ts`
  без зависимостей от React Native и проверяется в CI (`context_smoke.mjs`).
- Бюджет контекста: в Sharder — `context_length` модели, в Pointer — отдельная настройка,
  потому что окно чужой модели протоколом **не объявляется**.

## Мультимодальность

- **Sharder** принимает изображения ровно тогда, когда загружен projector (mmproj) и он
  сообщает о поддержке vision. То, что часть слоёв лежит на других телефонах, роли не
  играет: RPC переносит тензоры, а projector отрабатывает до них.
- **Pointer — нет.** Кадр `TASK` несёт `{mode, prompt}`, оба текстовые, и подпись раннера
  агента — `(prompt: string, context: string)`. Изображению негде проехать. Даже с
  расширенным кадром отвечающий телефон выбирает модель сам и может не иметь projector
  вовсе, поэтому возможность пришлось бы **объявлять в протоколе** — это работа для
  `AGENT_ANNOUNCE`, а не для кнопки в интерфейсе.

Приложение опрашивает это вживую и пишет причину на экране, а не прячет неработающую кнопку.

## Что доказано

19 smoke-тестов в `integration/chatterui_llamacpp/js/`, каждый гоняет **настоящие исходники
приложения** (Node 22 type-stripping импортирует `.ts` напрямую), плюс Python selftests и
conformance-векторы. Всё это — в `helix-ci.yml`.

Нативная часть (реальный hotspot, реальный RPC между телефонами) в CI не проверяется —
только на железе.
